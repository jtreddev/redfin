# Trends Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Trends tab showing 12 months of spending by group (Bills, Everyday, Habits, Fun & Wants, Saving), one category over time, and what changed this month; a this-month card on Home; plus four small fixes parked from project 1.

**Architecture:** Pure aggregation in `src/shared/trends.ts` over the existing ledger (`loadLedger` → `ledgerEntries` → `flowCents`), exposed by `GET /api/trends`; hand-written SVG chart components in `src/client/charts/`; a new `Trends` screen.

**Tech Stack:** Cloudflare Workers + D1, Hono, React 19 + Vite, Vitest (`tests/helpers/d1.ts`, `tests/helpers/api.ts`).

**Spec:** `docs/superpowers/specs/2026-10-18-trends-design.md`

## Global Constraints

- Counting rules are the budget's: `ledgerEntries` + `flowCents` (ignored, transfers and uncategorized transfer halves don't count).
- Group order and colors fixed: Bills, Everyday, Habits, Fun & Wants, Saving = dataviz reference categorical slots 1–5, light and dark.
- "Usual" = average of the last 3 full months. Habits yearly = usual × 12.
- "What changed": month-so-far scaled by days elapsed vs usual; top 5 up, top 3 down; ignore |difference| < 2000 cents; before day 7 compare the last full month instead and say so.
- Privacy: never list a partner's private transactions; partner Fun Money appears only as its category total; no drill-down into it.
- `/api/trends` months param 3–24, default 12; under 10 ms CPU for 3,000 rows.
- No chart library; no new runtime dependencies.
- Phone: 360px wide without horizontal scroll; tap targets ≥ 44px.
- Never push, deploy, or run `wrangler … --remote` (the controller releases).
- Committed files contain no real household data.

## Review Focus

1. A month with only partial data (current month) must not distort "usual" — usual excludes the current month. (Task 1 test `usual ignores the current month`.)
2. Refunds (positive amounts in expense categories) reduce that month's group total, never go below zero in a stacked segment drawing — draw negatives as 0 and show the true value in the tooltip/table. (Task 1 test `refund month`, Task 3 test `negative segment drawn as zero`.)
3. A category archived by project 1's migration but with old transactions still appears in history under its new category (data already re-pointed) — no "unknown category" rows. (Task 2 test.)
4. Partner's private charges never appear in `categories` as anything but their Fun Money total. (Task 2 test `partner privacy`.)
5. Dark mode charts readable: series colors switch to dark steps. (Task 4 browser check.)

### Task 1: Trends aggregation (pure)

**Files:** Create `src/shared/trends.ts`; Test `tests/trends.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export type GroupKey = 'bills' | 'everyday' | 'habits' | 'fun' | 'saving';
  export const GROUP_ORDER: readonly { key: GroupKey; section: string; name: string }[]; // Bills, Everyday, Habits, Fun & Wants, Saving
  export interface TrendsInput { entries: readonly LedgerEntry[]; categories: readonly { id: number; name: string; section: string; funMemberId: number | null }[]; months: readonly MonthKey[]; today: ISODate }
  export interface Trends { months: MonthKey[]; partialMonth: MonthKey; groups: { key: GroupKey; name: string; byMonth: Cents[] }[]; incomeByMonth: Cents[]; uncategorizedByMonth: Cents[]; categories: { id: number; name: string; group: GroupKey; byMonth: Cents[] }[]; usual: Record<GroupKey, Cents> }
  export function buildTrends(input: TrendsInput): Trends
  export interface Change { categoryId: number; name: string; soFar: Cents; usual: Cents; projected: Cents; diff: Cents }
  export function whatChanged(trends: Trends, today: ISODate): { basis: 'this-month' | 'last-month'; up: Change[]; down: Change[] }
  ```
